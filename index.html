Chương 01 · Foundations

Agent thật sự là gì?

Khác biệt nền tảng bạn phải nắm ngay ngày đầu tiên — phân biệt thẳng thắn giữa Workflow và Agent. Đây là đòn bẩy lớn nhất trong toàn bộ 24 giờ học tập.

I
§ 01 / Nền tảng
Định nghĩa chính xác — Workflow vs. Agent

Anthropic vạch một ranh giới sắc nét giữa hai loại hệ thống mà người ta vẫn gọi chung là "agent". Việc phân biệt đúng hai khái niệm này là điểm tựa quan trọng nhất bạn cần làm chủ trong ngày đầu tiên.

LoạiĐịnh nghĩaDùng khi nào
Workflow LLM và tools được điều phối qua các đường code đã định trước (predefined code paths). Chính bạn — kỹ sư — viết cây quyết định. Tác vụ có tính dự đoán được, khối lượng lớn, nhạy chi phí, hoặc có các nhánh được định nghĩa rõ ràng.
Agent LLM tự điều hướng việc dùng tools và luồng điều khiển (dynamically directs its own tool use and control flow) dựa trên phản hồi môi trường, trong một vòng lặp, cho đến khi hoàn thành tác vụ. Tác vụ mở, phụ thuộc đường đi, hoặc quá phức tạp để liệt kê trước các nhánh.
Nguyên tắc vàng của Anthropic

Hãy bắt đầu từ giải pháp đơn giản nhất có thể. Một lần gọi LLM được prompt tốt thắng được workflow. Workflow thắng được agent. Chỉ reach for agent khi tính linh hoạt và quyết định do model điều hướng ở quy mô lớn đủ để biện minh cho chi phí và độ trễ tăng thêm.

The augmented LLM — khối nguyên tử

Mọi agent và workflow đều được xây từ một khối nguyên tử duy nhất: augmented LLM — một model được bổ sung ba thứ: retrieval (thu thập ngữ cảnh), tools (hành động), và memory (lưu trạng thái). Toàn bộ guide này là cách kết hợp các augmented LLM lại với nhau.

Chương 02 · The Engine

Agentic Loop

Mọi Claude agent — dù đang viết code, làm deep research, hay dựng video — đều chạy cùng một vòng lặp ba nhịp. Anthropic xây Claude Code trên nền tảng này, rồi tách harness ra thành Claude Agent SDK để bạn có thể chạy nó.

II
§ 02 / Bộ máy
Vòng lặp ba nhịp — đầu não của mọi agent
01
Step one
Gather context

Agentic search (grep, tail, file reads), semantic search / embeddings, MCP calls, subagent queries. Vừa đủ để lập luận — không quá nhiều để làm ngộp context window.

02
Step two
Take action

Tool calls — built-in (Read, Write, Bash, WebSearch) hoặc custom. Model quyết định dùng tool nào, theo thứ tự nào, với tham số nào, dựa trên những gì vừa quan sát được.

03
Step three
Verify work

Chạy test. Đọc lại file. Kiểm tra output. Nếu có gì sai, quay lại bước 1 với context mới. Nếu đúng, trả về kết quả.

Hai cơ chế giữ vòng lặp này không vỡ trận. Compaction tóm tắt các turn cũ khi context sắp đầy. Subagents spawn các vòng lặp cô lập với context window mới hoàn toàn, trả về summary, và thoát — để parent agent không phải mang theo chi tiết của các sub-task.

Mental model CEO

Hãy nghĩ về Agentic Loop như chu trình PDCA (Plan–Do–Check–Act) của Deming, nhưng tự động hóa ở tốc độ silicon. Agent không đi thẳng đến kết quả — nó lặp đến kết quả, điều chỉnh từng vòng dựa trên ground truth từ môi trường.

III
§ 03 / SDK
Thư viện Python & TypeScript để dựng agent

SDK ship ở cả Python và TypeScript, cho bạn Claude cộng thêm toàn bộ tool loop của Claude Code dưới dạng một thư viện. Thay vì tự viết lại vòng lặp, bạn chỉ phát biểu ý đồ cấp cao — harness lo phần còn lại.

Agent SDK vs. Client SDK

LớpBạn được gìBạn phải viết gì
Client SDK Truy cập API trực tiếp. Bạn gửi messages, bạn parse tool-use blocks. Toàn bộ vòng lặp thực thi tool bằng tay. Toàn quyền kiểm soát — kèm toàn bộ trách nhiệm.
Agent SDK Claude + agentic loop sẵn có + file tools + Bash + subagents + MCP + hooks + permissions + context compaction. Chỉ phát biểu intent cấp cao. Harness lo phần còn lại.

Hello agent · Python
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions

async def main():
    async for message in query(
        prompt="What files are in this directory?",
        options=ClaudeAgentOptions(allowed_tools=["Bash", "Glob"]),
    ):
        if hasattr(message, "result"):
            print(message.result)

asyncio.run(main())
Hello agent · TypeScript
import { query } from "@anthropic-ai/claude-agent-sdk";

for await (const message of query({
  prompt: "Find and fix the off-by-one bug in src/parser.ts",
  options: {
    allowedTools: ["Read", "Edit", "Bash", "Grep"],
  },
})) {
  if (message.type === "result" && message.subtype === "success") {
    console.log(message.result);
  }
}

Dùng ANTHROPIC_API_KEY cho production. Anthropic không cho phép third-party developer dùng login claude.ai hoặc rate limit của gói monthly qua SDK, trừ khi đã được duyệt trước.

Token Economics — kinh tế chi phí

Đây là điều Anthropic ít viết ra nhưng cực kỳ quan trọng với SME Việt: mỗi tool call, mỗi subagent, mỗi lần compaction đều đốt token. Theo Anthropic Docs (2026), developer trung bình đốt ~$6/ngày khi dùng Claude Code. Với Agent Teams / multi-subagent, con số này có thể lên ~7× vì mỗi teammate mang context window riêng.

ModelKhi nào dùngNguyên tắc chi phí
Sonnet ~90% task hằng ngày: draft, grep, extract, classify, format. Nhanh và đủ thông minh cho bulk work. Default cho mọi subagent. Scale được lên khối lượng lớn mà không phá budget.
Opus Kiến trúc phức tạp, planning dài, reasoning nhiều bước, hoặc content có giá trị chiến lược cao. Reserved cho orchestrator layer và quyết định khó. Đắt ~5× Sonnet — dùng có kỷ luật.
Haiku Tool calls đơn giản, classification, routing, filter pass đầu cho data lớn. Rẻ nhất trong family. Tốt cho preprocessing pipeline trước khi đẩy vào Sonnet.
5 nguyên tắc giữ chi phí dưới $5/ngày

1. Default Sonnet · gọi Opus chỉ khi có lý do rõ ràng. · 2. Cho subagent model nhỏ hơn parent (parent Opus → worker Sonnet). · 3. Compaction khi context đầy 60% · đừng chờ đến 90%. · 4. Bỏ file lớn không cần thiết vào .gitignore để Claude không đọc. · 5. Set hard limit trong settings.json ngay từ đầu — đã có người burn $40 trong 1 giờ vì quên bước này.

Tám Building Blocks

Mọi agent có tính ứng dụng mà bạn xây dựng sẽ được ghép từ bộ nhỏ này. Thuộc từng khối — biết nó là gì, không phải là gì, và khi nào reach for it.

IV
§ 04 / Giải phẫu
Tám khối xây dựng cốt lõi
01 · Tools
Built-in & Custom ActionsHành động có sẵn và tự định nghĩa

Read, Write, Edit, Bash, Grep, Glob, WebSearch, WebFetch ship out of the box. Tự định nghĩa tools với decorator @tool (Python) hoặc createSdkMcpServer (TS). Tool chỉ là một hàm typed mà Claude có thể chọn gọi.

02 · MCP
Model Context ProtocolGiao thức kết nối mở

Chuẩn mở kết nối agent với tools và data bên ngoài — Slack, Gmail, database, Playwright. Tool name có dạng mcp__<server>__<action>. Chạy in-process hoặc qua stdio / HTTP.

03 · Subagents
Isolated Context WindowsAgent con với context cô lập

Subagent là một instance agent tách biệt mà main agent spawn ra để xử lý một subtask tập trung. Nó có context riêng, chạy, trả về summary, và thoát. Định nghĩa programmatic hoặc markdown trong .claude/agents/.

04 · Hooks
Callbacks on Agent EventsĐiểm móc trên sự kiện agent

Chạy code của bạn trên event như PreToolUse, PostToolUse, SessionStart, UserPromptSubmit. Hooks log, validate, auto-approve, hoặc block tool call một cách deterministic — không phải tin vào model.

05 · Permissions
What the Agent May DoPhạm vi quyền hạn của agent

Kiểm soát tool access qua allowedTools, disallowedTools, và permissionMode. Subagents không tự động kế thừa permission từ parent — scope riêng hoặc duyệt qua hook PreToolUse.

06 · Sessions
Conversation ContinuityTính liên tục của hội thoại

Mỗi lần gọi query() không kèm resume đều khởi động fresh. Bắt session_id từ init message, truyền lại lần sau, agent sẽ pick up đúng chỗ dừng lại.

07 · Context Management
Compaction & RetrievalQuản lý ngữ cảnh

SDK tự auto-compact các turn cũ khi window sắp đầy. Kết hợp với agentic search (grep filesystem), semantic search (embeddings), và subagents để giữ main thread gọn gàng.

08 · Agent Skills
Reusable ExpertiseChuyên môn tái sử dụng

Folder chứa SKILL.md + optional scripts, references, assets. Claude chỉ load metadata khi khởi động, đọc body khi relevant, và pull các file sâu hơn on-demand. Progressive disclosure cho tri thức agent.

Chương 05 · Skills

Agent Skills chuyên sâu

Skills là cơ chế mở rộng quan trọng nhất cần học sau Agentic Loop. Một Skill là một thư mục trên đĩa dạy Claude một năng lực cụ thể — format Word document, deploy app, xử lý PDF. Cấu trúc filesystem chính là kiến trúc.

Ba tầng Progressive Disclosure

Bí quyết khiến Skills vận hành hiệu quả là cơ chế progressive disclosure — "tiết lộ dần" — giúp context window của Claude không bao giờ bị quá tải.

1
Startup · Khởi động

Chỉ name + description metadata của mỗi Skill được pre-load. Không có gì khác chạm đến context window.

2
Invocation · Kích hoạt

Khi description match với task, Claude đọc toàn bộ body SKILL.md vào context.

3
Deep Dive · Đào sâu

Nếu task cần chi tiết cụ thể, Claude đọc các file tham chiếu (ví dụ references/FORMS.md) hoặc chạy scripts được bundle sẵn.

Ví dụ · SKILL.md
---
name: pdf-form-filler
description: Use this skill when the user needs to fill PDF forms,
  extract form fields, or flatten filled PDFs. Triggers on mentions
  of "PDF form", "fillable PDF", or uploaded .pdf files with forms.
---

# PDF Form Filler

Khi user yêu cầu bạn điền PDF form:

1. Chạy `scripts/inspect_fields.py <path>` để liệt kê field.
2. Map giá trị user cung cấp sang tên field.
3. Chạy `scripts/fill.py <input> <output> <fields.json>`.
4. Các edge case form-filling, đọc `references/EDGE_CASES.md`.
Kỷ luật authoring · Quy tắc vàng

Giữ SKILL.md dưới 500 dòng. Description là dòng quan trọng nhất trong cả file — đây là tín hiệu duy nhất Claude có khi quyết định có invoke skill không. Viết theo tình huống cần dùng, không phải theo tính năng skill làm được.

VI
§ 06 / Patterns
Sáu khung mẫu kết hợp được
i.
Augmented LLM— LLM được bổ sung

Một lần gọi LLM duy nhất đã kèm retrieval, tools, và memory. Là nguyên tử để xây mọi thứ khác.

Bạn có thể phát biểu task trong một prompt và model đã có đủ những gì cần.
ii.
Prompt Chaining— Xích prompt

Phân rã task thành chuỗi cố định các lần gọi LLM. Output bước N feed vào bước N+1. Deterministic và dễ debug.

Task tách rõ ràng thành các subtask có thứ tự và handoff sạch sẽ.
iii.
Routing— Phân luồng

Một classifier LLM dispatch input tới một trong nhiều handler chuyên biệt. Mỗi handler được tune riêng cho category của nó.

Input rơi vào các category rời rạc và bạn muốn prompt hoặc model riêng theo từng category.
iv.
Parallelization— Song song hóa

Chạy nhiều lần gọi LLM đồng thời. Hoặc sectioning (tách công việc thành các mảnh độc lập) hoặc voting (cùng prompt nhiều lần, tổng hợp kết quả).

Subtask độc lập với nhau, hoặc bạn cần nhiều góc nhìn / robustness kiểu majority-vote.
v.
Orchestrator–Workers— Điều phối viên và thợ

Một orchestrator LLM trung tâm phân rã task động, spawn worker LLM cho mỗi subtask, và tổng hợp kết quả. Sự phân rã do model điều hướng, không phải hardcode.

Bạn không thể đoán trước các subtask — chúng sinh ra từ input.
vi.
Evaluator–Optimizer— Đánh giá và tối ưu

Một LLM tạo. Một LLM khác phê bình. Generator sửa dựa trên feedback. Lặp cho đến khi evaluator hài lòng.

Có tiêu chí đánh giá rõ ràng và việc tinh chỉnh lặp đi lặp lại thực sự cải thiện output.

§ 07 / Thực hành
Code mẫu để chép chạy

Ví dụ 01 · Custom Tool (in-process MCP)

from claude_agent_sdk import query, ClaudeAgentOptions, tool, create_sdk_mcp_server

@tool("get_weather", "Fetch current weather for a city", {"city": str})
async def get_weather(args):
    # ... gọi weather API của bạn ở đây ...
    return {"content": [{"type": "text", "text": f"72°F and sunny in {args['city']}"}]}

server = create_sdk_mcp_server(name="tools", version="1.0", tools=[get_weather])

options = ClaudeAgentOptions(
    mcp_servers={"local": server},
    allowed_tools=["mcp__local__get_weather"],
)

Ví dụ 02 · Subagent cho parallel code review

const options = {
  agents: {
    "security-reviewer": {
      description: "Reviews code for auth, injection, and secrets issues. Use for any PR touching auth or input handling.",
      prompt: "You are a security-focused code reviewer. Flag issues with severity.",

    },
    "perf-reviewer": {
      description: "Reviews code for performance regressions. Use for hot-path changes.",
      prompt: "You are a performance engineer. Focus on allocations, N+1s, and async patterns.",
      tools: ["Read", "Grep", "Bash"],
    },
  },
};
// Parent agent giờ có thể dispatch song song cho cả hai reviewer.

Ví dụ 03 · PreToolUse Hook chặn lệnh nguy hiểm

async def guard(input, tool_use_id, context):
    if input["tool_name"] == "Bash":
        cmd = input["tool_input"].get("command", "")
        if "rm -rf" in cmd or "sudo" in cmd:
            return {"behavior": "deny", "message": "Destructive command blocked"}
    return {"behavior": "allow"}

options = ClaudeAgentOptions(hooks={"PreToolUse": [guard]})

Lý giải thang level · Sweet spot

Thang L1 → L7 map từ Builder Maturity Model. L4–L5 là sweet spot cho 80% CEO và operator: đủ để ship agent thật giải quyết bottleneck daily. L6 Orchestrator chỉ cần khi bạn có multi-repo hoặc Agent Teams với 3+ instance. L7 Autonomous (cron/scheduled tasks) là tầng cuối — khi hệ thống chạy lúc bạn ngủ. Đừng ép mình lên L6/L7 nếu L5 đã giải quyết vấn đề thật.

§ 09 / Tri thức
Sáu pitfall phổ biến
!
Reach for agent khi workflow là đủ. Agent chậm hơn, đắt hơn, khó dự đoán hơn. Bắt đầu đơn giản; thêm tính tự chủ chỉ khi chi phí đó đáng.
!
Nhồi nhét main context. Subagents và Skills tồn tại chính là để parent thread gọn gàng. Nếu bạn đang paste doc dài vào prompt, bạn đang chống lại harness.
!
Skill description yếu. Description nói skill làm gì thì trigger kém. Description nói khi nào invoke thì trigger tốt. Match theo tình huống, không phải theo tính năng.
!
Tin model để enforce safety. Dùng hooks để bảo vệ deterministic. Bất cứ gì cần xảy ra (hoặc không được xảy ra) phải nằm trong code — không phải trong prompt.
!
Quên subagents không kế thừa permission. Scope tools per-subagent, hoặc thêm rule auto-approval PreToolUse. Nếu không bạn sẽ thấy permission prompt ở những chỗ không ngờ.
!
Xây abstraction trước khi hiểu primitive. Lời khuyên của chính Anthropic: dùng API trực tiếp cho đến khi bạn cảm nhận được đau. Phần lớn "framework" thêm phức tạp nhiều hơn là giảm bớt.
∞
Multiplying zero is still zero · Domain > Tool. Cái bẫy lớn nhất và cuối cùng: tối ưu tool vô tận trong khi domain knowledge rỗng. Nếu bạn không hiểu sâu nghiệp vụ (Google Ads economics, supplement formulation, email deliverability, Shopify checkout flow), thì Claude dù mạnh cỡ nào cũng chỉ giúp bạn viết cái sai nhanh hơn. Cứ mỗi tháng, audit lại: bỏ tools và skills không dùng, đầu tư thời gian học domain. 3 skills tốt hơn 30 skills không ai nhớ.
Meta-Mastery · Cách kiểm tra mình

Khi đã qua 24 giờ và ship được capstone, câu hỏi không còn là "dùng tool gì" mà là "cái gì thật sự improve output?" Audit định kỳ. Subtract nhiều hơn add. Teach lại những gì đã học — blog, video, workflow chia sẻ nội bộ team. Cách tốt nhất để master là dạy lại.
